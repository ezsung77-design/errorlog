# 아파트 현장 펀치/체크리스트 관리 시스템 (제안 + 구현)

현장에서 **폰으로 사진 찍고 → 위치·내용 입력 → 구글 스프레드시트에 자동 축적**되는
단일 파일 웹앱과 Google Apps Script 백엔드입니다. 설치 없이 브라우저 주소만 공유하면 됩니다.

```
[현장 담당자 폰]                    [구글 계정 내부]
 punch/index.html  ──POST(사진)──▶  Apps Script  ──▶ Google Drive (사진 원본)
 (오프라인 저장:                     웹 앱(/exec)  ──▶ Google Sheets
  localStorage + IndexedDB)  ◀─GET(목록/마스터)─┘      ├ PUNCH  펀치 원장
                                                       ├ MASTER 드롭다운 마스터
                                                       └ LOG    변경 이력
```

## 1. 왜 이 구조인가

| 선택 | 이유 |
|---|---|
| 구글 시트를 DB로 | 별도 서버·비용 없음. 소장/발주처가 **시트를 그대로 열어** 필터·피벗·인쇄 가능 |
| 사진은 드라이브에 | 시트 셀에 이미지를 넣으면 무거워짐. 시트에는 **링크만**, 원본은 드라이브 폴더 트리(`현장/동`)로 정리 |
| 앱은 HTML 1개 | 앱스토어 배포·설치 불필요. GitHub Pages 링크를 카톡으로 공유 → 홈 화면에 추가하면 앱처럼 동작 |
| 로컬 우선(offline-first) | 지하·엘리베이터 홀 등 **전파가 끊기는 현장**에서도 등록 가능. 신호가 잡히면 자동 동기화 |
| 사진 자동 축소 | 원본 4MB → 1600px/JPEG 0.72 (약 200~400KB). 업로드 시간과 드라이브 용량 절감 |

## 2. 데이터베이스 설계 (Google Sheets)

### PUNCH — 펀치 원장 (1행 = 1펀치)

| 열 | 항목 | 설명 |
|---|---|---|
| A | ID | `P + 타임스탬프` 자동 발번. 병합 키 |
| B | 등록일시 | ISO (`2026-08-22T14:03:11`) |
| C | 수정일시 | 충돌 병합 기준(최신 우선, LWW) |
| D | 현장 | 설정에서 지정한 현장명 |
| E | 동 | 101동 |
| F | 호수 | 1502 |
| G | 실 | 거실/안방/욕실1 … |
| H | 부위 | 벽/천장/바닥/창호 … |
| I | 공종 | 도배/타일/도장/설비 … |
| J | 하자유형 | 균열/누수/오염/미시공 … |
| K | 중요도 | 긴급/중요/보통 |
| L | 제목 | 실+부위+하자유형 자동 조합 |
| M | 특기사항 | 자유 서술 |
| N | 상태 | 접수 → 조치중 → 조치완료 → 확인완료 (보류) |
| O | 담당업체 | 협력업체명 |
| P | 조치기한 | 초과 시 목록에 **기한초과** 표시 |
| Q | 완료일시 | 조치완료/확인완료 전환 시 자동 기록 |
| R | 등록자 | 설정의 사용자명 |
| S | 사진(조치전) | 드라이브 링크(줄바꿈 다중) |
| T | 사진(조치후) | 드라이브 링크 |
| U | 사진메타(JSON) | `[{pid,kind,fileId}]` — 앱이 썸네일 복원에 사용 |
| V | 삭제 | `Y` = 소프트 삭제(행은 남김) |

### MASTER — 드롭다운 마스터
열 = 항목 그룹(`현장 / 동 / 실 / 부위 / 공종 / 하자유형 / 중요도 / 상태 / 담당업체`).
**시트에서 값을 추가하면 앱의 선택 칩이 그대로 늘어납니다.** (설정 → 마스터 새로고침)

### LOG — 변경 이력
`일시 / 펀치ID / 변경필드 / 변경값 / 작업자` — 누가 언제 상태를 바꿨는지 추적.

### 드라이브 폴더 구조
```
펀치리스트_사진/
 └ ○○아파트 1단지/
    └ 101동/
       ├ 101동_1502_before_IMG….jpg
       └ 101동_1502_after_IMG….jpg
```

## 3. 설치 (15분)

1. 구글 드라이브에서 **새 스프레드시트** 생성 → 이름 예) `펀치리스트_○○아파트`
2. 확장 프로그램 → **Apps Script** → 기본 코드 삭제 후 [`apps-script/Code.gs`](apps-script/Code.gs) 전체 붙여넣기 → 저장
3. 상단 함수 목록에서 `setup` 실행 → 권한 승인 → `PUNCH/MASTER/LOG` 시트 자동 생성
4. **배포 → 새 배포 → 유형: 웹 앱**
   - 설명: `punch v1`
   - 실행 계정: **나**
   - 액세스 권한: **링크가 있는 모든 사용자** (사내만 쓰면 `조직 내 사용자`)
   - 배포 후 `https://script.google.com/macros/s/…/exec` URL 복사
5. 앱(`punch/index.html`)을 GitHub Pages 등으로 열고 **⚙ 설정**에 URL·현장명·등록자 입력 → 저장 → **연결 테스트**
6. 아이폰 Safari `공유 → 홈 화면에 추가` / 안드로이드 Chrome `홈 화면에 추가` → 앱처럼 사용

> 배포한 URL을 그대로 팀원에게 전달하면 각자 폰에서 같은 시트로 기록이 모입니다.
> 코드를 수정했다면 **새 배포**가 아니라 `배포 관리 → 편집(연필) → 버전: 새 버전`으로 올려야 URL이 유지됩니다.

## 4. 현장 사용 흐름

1. **등록 탭**: 촬영/선택 → 동·호수 입력 → 실·부위·공종·하자유형·중요도 칩 탭 → 특기사항 → `펀치 등록`
   - 같은 세대에서 연속 등록 시 `위치 유지하고 비우기` 사용
2. **목록 탭**: 상태·공종 필터, 동/호수/내용 검색 → 카드 탭 → 상세에서 **조치후 사진 추가**, 상태·업체·기한 변경
3. **현황 탭**: 전체/완료/잔여/기한초과/긴급/완료율 + 상태·동·공종별 막대 → `CSV 내보내기`로 보고서 첨부
4. **⟳ 동기화**: 대기 사진 업로드 → 변경분 시트 반영 → 시트 최신본 내려받아 병합.
   저장할 때마다 자동으로도 1회 실행되며, 오프라인이면 주황 점(●)으로 미동기화 표시가 남습니다.

## 5. 알아둘 점 / 한계

- **동시 편집**: 같은 펀치를 두 사람이 동시에 고치면 `수정일시`가 늦은 쪽이 이깁니다(LWW). 세대별 담당을 나누면 충돌은 사실상 없습니다.
- **사진 공개 범위**: 앱에서 썸네일을 보려면 파일이 *링크가 있는 사용자 보기* 권한이어야 합니다. 조직 정책상 외부 공유가 막혀 있으면 조직 계정으로 로그인한 사람만 사진이 보입니다(기록 자체는 정상).
- **Apps Script 할당량**: 무료 계정 기준 1일 실행 20,000회 / URL Fetch 등 제한이 있습니다. 하루 수백 건 규모의 현장에는 충분합니다.
- **한 장당 업로드**는 순차 처리라 사진 20장을 한 번에 올리면 30초 내외 걸릴 수 있습니다(진행 중 토스트 표시).
- 로컬 데이터는 브라우저에 저장되므로, **캐시 삭제 전 반드시 동기화**하세요.

## 6. 확장 아이디어 (다음 단계)

- QR/NFC를 세대 현관에 부착 → 스캔하면 동·호수 자동 입력
- 상태가 `조치완료`로 바뀌면 담당업체에 Gmail 자동 발송(Apps Script 트리거)
- 시트에서 **세대별 펀치 리스트 PDF** 자동 생성(문서 병합) → 인수인계 서류로 사용
- 도면 이미지 위에 핀 찍기(좌표 저장 컬럼 추가)
- 사진 AI 자동 분류(하자유형 추천) — 저장소 루트의 오답 로그 앱과 동일한 Gemini 호출 방식 재사용 가능
